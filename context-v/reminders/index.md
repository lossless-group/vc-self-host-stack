# Reminders

* [Creating a Railway service fires a build before you can configure it](Creating-a-Railway-Service-Fires-a-Build-Before-You-Configure-It.md) - The build that starts the instant a service is created runs with no domain, no variables, and the Dockerfile's ARG defaults. Read anything from it and you will draw the wrong conclusion about what Railway does and does not pass to a build.
* [The goal is multi-tool functionality from one MCP server](Goal-is-to-Enable-Multi-Tool-Functionality-from-One-MCP-Server.md) - Clients live in Claude Desktop, not a terminal. Everything we build has to arrive as one connector they never have to think about again.
* [railway config pull does not pin database images — read the plan](Railway-IaC-Pull-Does-Not-Pin-Database-Images.md) - A pulled Railway IaC config re-declares every postgres() and redis() at the helper's default version. Applying it unchanged proposes a major-version upgrade on live databases.
* [Submodules detach because .gitmodules never said which branch](Submodules-Detach-Because-gitmodules-Never-Said-Which-Branch.md) - The parent pins a raw SHA, so every submodule update lands on a detached HEAD. Declaring branch and update in .gitmodules fixes it once for every clone — but the bulk scripts that promise to fix it are exactly the things that have historically detached submodules AND clobbered their remotes.
